# 评测不经过聊天，使用独立库与文件结果

评测用于验证 Agent 在固定基线上的任务结果，并比较提示词、模型、Skill 和上下文组装的改动。聊天与评测共用 `AgentChatService.runTask`。聊天入口投递回复，评测入口传入独立项目的用户、群和 Agent 身份，`triggerMessageId` 留空。两种入口共用运行记录与工具轨迹。

## 运行与判分

- JUnit 通过 `QGENTS_EVAL=true` 显式启动 `EvalRunner`。Runner 准备用例、执行、判分并写报告。用例验收未达标记入报告，评测环境或判分器故障由 JUnit 报错。
- 评测使用独立 MySQL 库和 `PROJECT_DATA_ROOT`。每次尝试从固定的群历史、项目记忆、群记忆和 Agent 私有记忆起步，代码用例另从固定提交创建新 worktree。可控模型用于验证评测器能稳定判出已知结果，真实模型重复尝试用于测量通过率。
- 整次运行超时后，经 `RunLifecycle` 请求取消根运行并等待命令、子 Agent 和工作区会话收尾。超时取消已完成时记 `TIMEOUT`，收尾超过时限记 `ERROR` 并保留现场。
- 代码用例保存最终文件树与 Git 状态，再用独立验收环境运行评测器持有的隐藏测试。记录代码测试结果，并按任务要求记录提交或 PR 交付结果。
- `data/evals/` 保存批次汇总和每次尝试的 JSON，包含运行身份、用例和环境版本、终态、耗时和判分证据，供跨批次比较。

## 实施顺序

1. 抽出共享运行入口。
2. 跑通首条项目记忆用例及超时验收。
3. 接入固定基线、独立判分和代码交付。
